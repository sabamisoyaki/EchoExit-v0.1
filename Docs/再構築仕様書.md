## 1. ゲーム概要

**Backrooms のような空間に迷い込んだ一般青年が、怪しいオブジェクトに固有の「儀式」を試して異変を認識し、ときには襲ってくる異変から逃げ、6回連続で正しく判断して脱出を目指す一人称3D異変探索ホラー。**

八番出口系の「前回との差分を暗記する」遊びではなく、**対象を疑い、自分で検証して異変そのものを発見する**ことが核です。

| 項目 | 確定内容 |
|---|---|
| 正式タイトル | 666号扉（プロジェクト名 EchoExit は第二案） |
| ジャンル | 一人称3D異変探索ホラー / 1人用 |
| プラットフォーム | Windows PC |
| 入力 | キーボード＋マウス、ゲームパッド |
| 言語 | 日本語のみ |
| 標準プレイ時間 | 約20分 |
| 途中保存・チェックポイント | なし |
| ヒント・異変図鑑 | なし（経験で学ぶ） |
| ホラー表現 | とことん怖い方向 |

## 2. ハード制約（破ってはいけない）

1. **正誤ルール**: 異変なし → 前進、異変あり → 後退。複数異変のラウンドでも1つでもあれば後退が正解。
2. **クリア条件**: 6連続正解。不正解で連続数は0に戻る。
3. **異変ラウンドの確率**: 66.6%。
4. **ステージJSONは完全互換**: 既存のJSONファイルが無変更で読めること。フィールド名を変えない（§5）。
5. **決定論**: 同じ異変に同じ操作をすれば毎回同じ結果。儀式の成否にランダムを入れない。
6. **ペナルティなし**: 通常オブジェクトに儀式を試しても何も起きない。
7. **フレームレート非依存**: 30 / 60 / 120fps で発動までの時間が実用上同じ。
8. **追跡型の安全規則**: 1ステージ1体まで。認識から最低1.2秒は捕獲しない。認識演出中は捕獲判定を無効にする。
9. **扉は操作で決定**: 前進・後退・最終出口は接触判定ではなく、扉へのインタラクト操作で確定する。
10. **EditMode はプレイヤー公開機能**: 編集できるのは既存フィールドへの通常／異変オブジェクト配置のみ。フィールド作成や儀式の新規作成は対象外。
11. **異変専用の操作ボタンを増やさない**: 儀式は移動・視点・叩く・扉操作の組み合わせで作る。

## 3. ゲームループ

### 3.1 進行

1. タイトルからプレイ開始。連続正解数とラン状態を初期化する。
2. ラウンドの部屋を抽選し（§3.2）、通常オブジェクトと異変オブジェクトを配置する。
3. 制限時間のカウントを開始する。
4. プレイヤーは探索し、儀式を試す。儀式が成立すると認識バナーを短く表示する（視界を塞がない）。追跡型なら「出口へ逃げろ」を併記する。
5. 扉を操作すると判定する。判定中は入力をロックし、正誤フィードバックを見せる。
6. 正解なら連続数 +1、不正解なら 0。6に達したら通常脱出エンディングへ進む。それ以外は次のラウンドを構築する。
7. 捕獲・時間切れはその場でランを終了し、終了種別を区別して終了画面へ進む。

| 終了種別 | 条件 | 表示 |
|---|---|---|
| `Escaped` | 6連続正解 | 通常脱出 |
| `Caught` | 追跡型に捕獲された | 異変に捕まった（異変名を保持。将来は異変ごとの専用エンディング） |
| `TimeExpired` | 制限時間が0になった | 時間切れ |

### 3.2 部屋の抽選規則

旧実装で確定し、テストで固定されていた規則です。**そのまま引き継いでください。**

- `wantAnomaly = Random < 0.666`
- **異変ONのラウンド**: 異変アイテム（`isAnomaly: true`）を含む部屋からだけ選ぶ。
- **異変OFFのラウンド**: すべての部屋から選ぶ。異変あり部屋を選んだ場合は `isAnomaly: true` のアイテムを配置しない。
  - 理由: 異変なし部屋だけを使うと「部屋の見た目＝異変の有無」が固定され、間取りの暗記だけでクリアできてしまう。
- 直前と同じ部屋は、候補が2つ以上あれば除外する。
- 希望側に候補がない場合は反対側から選び、**実際に構築した内容で正誤を判定する**。
- どちらにも候補がなければ現在の部屋を再利用する。

### 3.3 「異変あり」の決め方

**ラウンドの正解は、実際に配置した異変オブジェクトの数（1以上か）でデータとして確定させてください。**
旧実装はタグ文字列（しかも綴り誤りの `"Anomary"`）でシーンを再スキャンして判定しており、壊れやすい構造でした。

### 3.4 数値一覧

| パラメータ | 値 | 状態 |
|---|---|---|
| クリアに必要な連続正解 | 6 | 確定 |
| 異変ラウンド確率 | 0.666 | 確定 |
| 1ラウンドの異変上限 | 3 | 暫定（調整可能にする） |
| 制限時間 | 180秒、ラウンド開始から | 暫定（調整可能にする） |
| インタラクト・注視の最大距離 | 4m | 旧実装値 |
| 追跡速度 / 捕獲距離 / 猶予 | 2.8 m/s / 1.1 m / 1.2 秒 | 設計書・旧実装で一致 |
| 追跡速度の上限 | プレイヤー移動速度の75%以下 | 設計書 |

## 4. 異変システム

### 4.1 状態遷移

```text
休眠 → 儀式の入力開始
         ├─ 失敗・中断 → 休眠 または 進捗リセット
         └─ 成立 → 認識現象
                     ├─ P/R型 → 現象完了（ラウンドは異変ありのまま）
                     └─ H/E型 → 猶予 → 追跡開始
                                    ├─ 出口到達 → 逃走成功（その後、後退扉を操作して判定）
                                    └─ 捕獲 → ゲームオーバー / 特殊エンディング
```

- 穏やかな異変をすべて認識することは、扉を選ぶ条件ではない。
- 儀式を使わず観察だけで見抜ける異変も存在してよい。

### 4.2 儀式ランタイムの方針

旧実装は「異変ごとに儀式の種類を enum で1つ持つ」構造で、異変が増えるたびに専用コードが増えました。
新実装では、設計書 §5 のとおり**基本条件を順番に評価するシーケンス**として作ってください。

MVPで必要な基本条件:

| 条件 | 内容 |
|---|---|
| `Gaze` | 視線の中央に一定時間入れる |
| `LookAway` | 注視を完了した後、視線から外す |
| `Hit` | 注視中に叩く |
| `EnterRadius` | 指定距離まで近づく |
| `ExitRadius` | 近づいた後、指定距離まで離れる |
| `RemainStill` | 移動を止めて一定時間静止する |
| `CrossThreshold` | 対象の背後を通過する |
| `AudioCue` | 固有音が鳴ったことを起点にする |

各ステップに「制限時間（timeWindow）」「失敗時にどこまで戻すか」を持たせます。

### 4.3 知覚の定義（旧実装で使っていた解釈）

設計書に厳密な定義がないため、旧実装の解釈を初期値として示します。変更する場合は企画担当と合意してください。

| 知覚 | 旧実装での定義 |
|---|---|
| 注視している | カメラ中央からのレイキャストが4m以内で対象のコライダーに当たっている |
| 目を外している | 上記が当たっていない（遮蔽物で隠れた場合も含む） |
| 静止している | プレイヤーの移動速度が 0.12〜0.18 m/s 以下 |
| 背後を通過した | 対象ローカル座標のZが0以上から -0.15 未満へ変わり、かつ指定距離内 |
| 振り返った | 視線方向と音源方向のなす角が35°以内 |

視線・距離・速度はフレームごとに1回だけ計算し、全異変へ配る構成を推奨します。

### 4.4 MVPの異変7種

儀式の値は**設計書の値**です。旧実装と値が違う異変があります（§10）。

| ID | prefabId | 名称 | 分類/危険度 | 儀式 | 認識現象 |
|---|---|---|---|---|---|
| ANM-001 | `changeColorBox` | 目を離した箱 | P / D0 | 1.5秒注視 → 1.0秒目を外す | 赤く変色＋逆再生音 |
| ANM-002 | `anomaryShirinkBox` | 痩せる箱 | P / D0 | 2.5m以内に接近 | 0.8秒で元の8%へ縮小、5m離れると復帰 |
| ANM-003 | `DollPrefab` | 帰ってくる人形 | R / D1 | 2.5m以内に接近 → 6秒以内に4.5m以上離れる | 黒く変色して消え、5秒後に向きを変えて戻る |
| ANM-004 | `bears` | 叩き起こし | H/E / D2 | 叩く | 振り向いて立ち上がり、1.2秒後に追跡 |
| ANM-005 | `ChairPrefab` | 席を数える椅子 | P / D0 | 背後を通過 → 4秒以内に1秒注視 | 床の影だけが1→2→3個と増える |
| ANM-006 | `wall` | 呼吸する壁 | R / D1 | 3m以内で壁から目を外し2.5秒静止 | 壁が一度膨らみ、背後で息を吐く |
| ANM-008 | `footstepEcho` | 一歩多い足音 | R / D1 | 余分な足音から0.8秒以内に停止 → 2秒静止 → 振り返る | 直前の位置に濡れた足跡と人影 |

`prefabId` の綴り（`anomaryShirinkBox` など）は既存JSONとの互換のために**そのまま残してください**。

各異変の弱い手掛かり、正常版の挙動、将来の強化案は設計書 §6 を参照してください。

### 4.5 異変定義はデータで持つ

設計書 §11 のとおり、異変定義を配置JSONとコードから分離してください（ScriptableObject など）。

| フィールド | 用途 |
|---|---|
| `anomalyId` | `ANM-001` 形式の不変ID |
| `prefabId` | 見た目の解決。旧JSONからの変換キー |
| `behaviorClass` / `dangerLevel` | P/R/H/E、D0〜D3（プレイヤーには非表示） |
| `ritualSteps` | 条件、順序、時間、リセット規則 |
| `recognitionEffect` / `threatProfile` | 演出、追跡パラメータ |
| `endingId` | 専用エンディング（なければ共通の捕獲エンディング） |
| `placementRules` / `userStageAllowed` | 配置条件、ユーザーステージで使えるか |

ステージJSONは配置と異変IDだけを持ち、儀式の時間や危険度を持たせないこと。これで公式側の調整が古いユーザーステージにも反映されます。

### 4.6 受入基準

設計書 §13 の全項目を、各異変の完了条件にします。特に次の3点は自動テストで保証してください。

- 通常版は、すべての儀式候補操作に反応しない。
- 異変版は、仕様どおりの手順だけで100%発動する。
- 30 / 60 / 120fps 相当の時間刻みで発動時間が同じ（時間を注入してテストする）。

## 5. ステージデータ

### 5.1 JSONスキーマ（互換必須）

```json
{
  "scenes": [
    {
      "sceneId": 2,
      "anomalyHouse": true,
      "items": [
        {
          "prefabId": "ChairPrefab",
          "position": { "x": -1.0, "y": 0.5, "z": 2.0 },
          "rotation": { "x": 0, "y": 20, "z": 0 },
          "isAnomaly": false
        }
      ]
    }
  ]
}
```

| フィールド | 意味・規則 |
|---|---|
| `sceneId` | 部屋ID。1以上の整数 |
| `anomalyHouse` | 読み書きはするが、分類には使わない。異変ありかどうかは `items` の `isAnomaly` から導出する（旧実装も同じ） |
| `prefabId` | 配置物のID。**未知のIDでもデータを捨てず保持し、警告だけ出す** |
| `position` | ワールド座標（m） |
| `rotation` | オイラー角（度） |
| `isAnomaly` | そのオブジェクトが異変かどうか |

- 同じ `sceneId` のブロックが複数あれば、**読込時に1つへマージ**する。
- **保存時は同じ `sceneId` のブロックをすべて置き換え**、`sceneId` 昇順に並べる。
- 新規 `sceneId` は「1から数えて最初の空き番号」にする。

### 5.2 保存場所と初回データ

- 保存先: `Application.persistentDataPath/Saves/anomalies.json`。ファイル名は定数1箇所で管理する。
- 保存ファイルが存在しない、または中身が空なら、同梱の `DefaultAnomalies.json` を展開する。
- 同梱データは現在9ステージ（企画書には6ステージと書かれていますが、実データは9件です）。

### 5.3 互換テスト

`DefaultAnomalies.json` を読み込んで書き戻し、フィールド名と値が変わらないことをテストで保証してください（旧テスト `ExistingJsonSchema_RoundTripsWithoutChangingFieldNames` 相当）。

## 8. 推奨アーキテクチャ

旧実装の反省から導いた推奨です。これより良い案があれば、理由を添えて変更して構いません。

1. **ラウンドごとにシーンを再ロードしない。** ゲームシーン内でワールドのルートを破棄・再構築する。ラン状態（連続正解数、現在の部屋、終了種別）は1つのオブジェクトに集約し、`static` 変数でシーンをまたいで持ち回らない。
2. **異変定義はデータ、儀式は汎用ランタイム。** prefabId ごとの `switch` をコードに書かない（§4.2、§4.5）。
3. **純粋なロジックを MonoBehaviour から分離する。** 抽選、検証、儀式の状態機械、JSON入出力は Unity に依存しないクラスにし、EditMode テストで検証する。時間は外から渡す。
4. **入力は Input System だけにする。** 旧 Input Manager と併用しない（旧プロジェクトは `activeInputHandler: 2`＝併用設定だった）。
5. **文字列を定数にまとめる。** シーン名、保存ファイル名、レイヤー名などをコードに直書きしない。
6. **1つの挙動に実装は1つ。** 旧版を残して実行時に無効化する移行方法はとらない。

## 9. 旧実装で踏んだ地雷（再発させないこと）

| # | 起きたこと | 対策 |
|---|---|---|
| 1 | `??` / `?.` が Unity の擬似 null を素通りし、破棄済みオブジェクトを参照した | `UnityEngine.Object` には `== null` か `TryGetComponent` を使う |
| 2 | Shift-JIS で保存されたソースの日本語が文字化けした | 全ソースを UTF-8 にし、`.editorconfig` で強制する |
| 3 | ファイル名とクラス名が違った（`PlayerController.cs` の中身が `class PlayerMovement`） | ファイル名とクラス名を必ず一致させる |
| 4 | スクリプトは GUID で参照されるため、名前検索で「未使用」と誤判定した | 削除は `.meta` ごと行い、GUID 参照を確認してから消す |
| 5 | `static` の連続正解数がタイトルに戻っても残った | §8-1 |
| 6 | `SceneManager.LoadScene` は存在しないシーン名でも例外を投げず、フォールバックが動かなかった | 事前に `Application.CanStreamedLevelBeLoaded` で確認し、シーン名は定数にする |
| 7 | 縮小処理がフレーム単位の加算で、フレームレートによって速さが変わった | `deltaTime` を使い、時間注入テストで確認する |
| 8 | 「チェック」関数がセーブフォルダに空ファイルを作る副作用を持っていた。さらにどのボタンからも呼ばれない孤児オブジェクトの `Start()` がタイトル表示のたびに実行されていた | 判定関数に副作用を持たせない。使わないオブジェクトはシーンに残さない |
| 9 | プレイヤーに移動スクリプトが2系統付いており、実行時に片方を無効化していた | 移動系は1つにする |
| 10 | 異変の有無を、綴り誤りのタグ `"Anomary"` によるシーンスキャンで確定していた | §3.3 |
| 11 | 保存ファイル名の規約が場所によって違った（`anomalies.json` と `anomaly_{suffix}.json`） | 定数1箇所で管理する |
| 12 | テキスト入力中にショートカットが反応し、誤保存・誤遷移が起きた | §6 |
| 13 | 複数のAIエージェントのPRが統合ブランチに溜まり、`main` に戻らないまま放置された | `main` を常に統合先にし、小さなPR単位でテスト合格を条件にマージする |

## 10. 設計書と旧実装の食い違い（実装前に決めること）

設計書は自らを「基準文書」としているため、**特に指示がなければ設計書の値を採用**してください。
旧実装の値がプレイテストで調整された結果なのか、単に設計書が未反映なのかは記録が残っていません。企画担当に確認することを推奨します。

### 儀式の値

| 異変 | 設計書 | 旧実装 |
|---|---|---|
| ANM-002 痩せる箱 | 0.8秒で8%へ縮小 | 一定速度（1.2/秒）で縮むため、所要時間がオブジェクトの大きさで変わる |
| ANM-003 帰ってくる人形 | 2.5m → 6秒以内に4.5m | 2.5m → 9秒以内に5.0m |
| ANM-005 席を数える椅子 | 背後通過 → 4秒以内に1秒注視 | 3.2m以内で背後通過 → 6秒以内に0.65秒注視 |

### 抽選・検証ルール

| 項目 | 設計書 | 旧実装 |
|---|---|---|
